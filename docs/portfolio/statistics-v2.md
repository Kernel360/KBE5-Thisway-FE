# CHANGE-FE-006: 완료 운행 가동률과 통계 품질 표시

- 날짜: 2026-09-06
- 기준: `ec1c819`, `codex/frontend-dependency-security`
- 상태: Verified (화면/fixture 계약 범위)
- 기존 팀 회사 통계 화면을 대상으로 한 개인 현대화. 원 팀 전체 UI를 개인 구현으로 주장하지 않는다.

## 문제와 선택

BE totalDrivingTime은 분인데 기존 화면은 h를 붙였다. BE가 GPS 개수 대신 완료 Trip 시간
기준 V2로 바뀌므로 구버전과 미집계를 새 공식의 0처럼 표현하지 않게 해야 한다.
BE의 CHANGE-030/ADR-008과 한 계약이며 두 저장소를 함께 검토한다.

- [x] 300분 → 5시간 0분 표시
- [x] quality.formulaVersion=2 및 coveredDays>0일 때만 새 통계 값 표시
- [x] 기간 coverage/이전 공식 제외/미종료 건·일 안내
- [x] GPS는 저장된 관측 수이며 수신율이 아니라고 표시
- [x] 단위/가동률 의미/현재 active fleet·집계일 평균·늦은 OFF 보정 안내
- [x] unit/browser/build 회귀

무조건 값을 표시하는 fallback 대신 legacy에는 `-`와 재집계 안내를 채택했다. 구 BE의 숫자를
V2로 오인시키는 것보다 의미를 보존하는 선택이다. 새 BE + 구 FE에서는 경고/분 표시가
빠지므로 두 버전의 배포 조합을 완전 호환으로 간주하지 않는다.

## 흐름

기존 인증 통계 API → quality 해석 → 현재 기준의 coveredDays 확인 → 분을 시간/분으로 변환
→ 가동률과 GPS 관측 수를 다른 영역으로 표시. GPS 분모를 추정하지 않는다.
시간별 그래프/최대·최소 시간대도 구버전 또는 미집계에서는 숫자를 숨긴다.
시동 위치 통계는 일별 V2 저장값과 달리 현재 원천의 기간 조회라는 점을 명시했다.

## 검증

- `npm test`: 11개 통과(기존 SSE 8 + 통계 표시 3).
- `npx playwright test`: 12개 통과, 2.9초(기존 9 + 통계 실제 component 3).
- `npm run build`: 성공, 3.29초. 976.17kB/gzip 298.91kB main bundle 경고는 유지.
- 통계 browser는 API fixture를 사용한다. 지도는 기존 test stub이며 Kakao/운영 DB와 연결하지 않는다.
- BE는 별도 실제 MySQL/HTTP 테스트로 응답 계약을 검증한다. 전체 회사 업무 live E2E를 한 것은 아니다.

## 한계와 학습

가동 시간에는 정차/공회전이 포함된다. 미집계는 0이 아니고, 미종료 일별 누계는 고유 Trip 수가
아니다. GPS 관측 수 역시 수신율이 아니다. 분모와 단위를 화면에서도 설명해야 한다.
자동 보정/기간별 실제 fleet 이력/수신율/성능 개선은 미완료다.

1. 왜 이전 서버 데이터에 `-`를 보여 주나요?
   - 같은 필드라도 공식이 다르기 때문이다. metadata 없이는 새 의미를 보증할 수 없다.
2. 300h를 5시간으로 바꾼 것은 성능 개선인가요?
   - 아니다. API 분 단위를 잘못 표시하던 정확성 문제를 고친 것이다.
3. 집계 1/3일은 2일이 쉬었다는 뜻인가요?
   - 아니다. 미집계/구버전을 별도 표시하고 집계된 날짜만 평균에 포함한다.

AI가 BE-FE 계약 조사, 구현과 fixture, 회귀 및 문서 초안을 수행했다. 사용자 본인의
독립 설명은 제출 전 확인해야 한다. 기존 숫자를 새 의미로 silently 표시하는 대안은 거절했다.
